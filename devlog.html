🦆 How I built Duckdoku

A duck logic puzzle, built solo with AI tools

by Tetra Developers

Duckdoku is a small Sudoku-style puzzle game: one duck per row, one duck per column, one duck per color, and no two ducks touching. No numbers, no math — just looking and thinking. This page is the honest story of how it got made: which tools I used, what I paid for art, and what came from an asset store instead of being generated.

I copied the idea for Duckdoku from Meowdoku, a cat version of the same puzzle already on Google Play. I liked the rules, so I rebuilt the game myself with my own ducks, art, and sounds, in my own style — not a copy-paste of its code or art.

The tools

I built the whole game inside Claude Code, Anthropic's coding assistant, talking to it like a teammate instead of writing every line myself. The model behind it was Claude Sonnet 5.

Claude didn't just write code in a text editor and hope it worked — it actually ran and drove the Unity Editor directly, using two things:

  • Unity CLI — Unity's own command-line tools, for builds and automation. docs.unity3d.com/Manual/CommandLineArguments.html
  • An MCP server for the Unity Editor — MCP (Model Context Protocol) is an open standard that lets an AI assistant call real tools instead of just talking. Through it, Claude could create GameObjects, edit scripts, press Play, take screenshots of the running game, and trigger real Android builds, all inside my actual Unity project. modelcontextprotocol.io

That combination is how features got built, tested with real gameplay (not guesses), screenshotted, and fixed in the same conversation.

On tokens: Claude Code doesn't hand me a running total of tokens spent across a project like this one, built over many separate conversations across several days — so I can't give an exact number here without making one up. What I can say honestly: it was a lot of back-and-forth, a lot of small fixes, and more than one rebuilt Android app bundle along the way.

The art

For the duck characters, icons, and store art, I gave Claude my own OpenAI API key. Claude generated the images as sprite sheets — several poses or frames in one image, cheaper than generating each one separately — and then cut each sheet into the individual sprite images the game actually uses.

The generated sprite sheets, before Claude cut them into individual images

Every image was made with OpenAI's image generation API. Before generating anything, Claude estimated the cost first and got my go-ahead. Total real spend on art for this project, checked directly on the OpenAI usage dashboard:

The sound

Sound effects and music came from two places:

  • Paid asset packs from the Unity Asset Store — a casual game SFX & music pack, a second casual sound effects pack, and a cartoon particle effects pack for the visual effects. I won't list which exact sound plays for which exact action — just that the game's audio and effects are built from these licensed packs.
  • A few custom sound effects generated with ElevenLabs, for moments the asset packs didn't quite cover (like the life-lost sound and the game-start chime).
